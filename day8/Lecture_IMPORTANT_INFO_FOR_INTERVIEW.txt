2. Garbage Collection (in detail), Reflection


HEAP Memory has 3 Sections: Nikhil's diagram is in format 0		1		3, not stacked

Generation 0:
	- new objects are created in 0 , they start getting full 


Generation 1:

	- Once level 0 starts getting full, Common Language Runtime performs a check for which objects are not active, idle, dead(logged out), 
		low priority objects, etc. the CLR will move to Level 1 which makes more space for new objs in Level 0 
		
		Once Level 0 is full, new objects starts getting created in Level 1
			- ten the object checks by CLR happen in Level 0 & 1 and move to Level 2

Generation 2:
	- Finally, new objects are created in Level 2. When it becomes full, it will CRASH. CLR will not destroy / delete objects or free-up memory



 COMPONENT GARBAGE COLLECTION TO THE RESCUE
 
		GC comes RANDOMLY at ANY time to see which objects are not active, idle, dead(logged out) that will clear those objects and reclaim memory.
		
		BUT, developers can call it: GC.Collect() - method to force clearing the objects from every generation

3. Common Language Runtime Components 

top -> bottom

	a. Loader
			This loads the application inside APPDOMAIN, it performs check against CTS (Common Type System) and CLS (Common Language System)
			  - checks like a bouncer that the type, language is all legit
	
	b. JITter - knows what OS it's running on, converts MSIL code -> machine language == THE COMPONENT NAME
		- JIT Just In Time compiler, compiles code -> MISIL == THE PROCESS
	
	
	c. Thread Manager - parallel executions, parallel operations, run multiple functionalities in parallel 
	
	d. Security Manager / Marshaller 
	
	e. COM(Component) Manager
				- allows interaction with non-.NET applications
				
	f. Code Manager
			- taking pointer from HEAP -> CODE on memory stack 
	
	
	g. Garbage Collector
			- this works on the objects in HEAP and destroys objects which are IDLE, timedOUT, or unused.
			
			- Comes in 3 stages 
			
			
	h. Exception Handler
	
	i. MISIL code -> to native binary code (deprecated, no longer supported by microsoft)
	
			- so you could theoretically skip the JITTER component and run just the binary code on windows.

									Serialization
									
										- is a process to Persist (save, but use persist) the object from memory into storage
									
									Deserialization
										
										- is a process to get the object in the original state from storage into memory
									
On RAM, inside the APPDOMAIN, in the HEAP say you have an object that stores A LOT of information, a lot of properties. 
		Then you make changes to it, and it changes in  memory.
			Then you close the application, and the object gets destroyed in RAM. Including the things you changed about the obj.
			
			How could you save it? 
			
			MICROSOFT TO THE RESCUE!!!
			
			
					Serialization Process
					
			Object Copy is sent to some File, Database, or Machine/Device .Serialize()
			
			
					Deserialization PROCESS
					
			The object copy is sent from File(.xml, .jsone, binary)/DB/Machine/Device back to APPDOMAIN
			
			So transactions - what a user did on the FE - saved most commonly in .JSON file
			
	Types Of Serialization:
	----------------------
		1. Binary Serialization - stores the object in binary format -- BinaryFormatter
		
		2. XMLSerializer - stores the object in xML format -- XMLSerializer
		
		3. JSONSerializer - stores object in json format for REST API
		
		4. SOAPFormatter - stores the object in XML based SOAP format for web services

					Reflections

Reflection is used for 2 things:

	1. To explore the metadata from an .dll or .exe 
			want to know what the Namespaces in the exe/dll
			What are classes
			What are the properties
			What are the list of methodsWhat are the list of enums
			What are the list of parameters
			What are constructors
			
			by using System.Runtime.Reflection 
	
	2. To create the object at runtime by user choice e.g. if my bankingLIB has 200 classes / types of accounts, a very bad program would use if conditions
																																	or switch cases
				
				if we want to remove / discontinue some accounts we will have to make changes to exe/dll 
				
				if we want to add new account we will have to do the same thing. 
				
				this isn't possible. 
				
				Instead, users can choose which account they want to create, select it and reate the object at runtime.
